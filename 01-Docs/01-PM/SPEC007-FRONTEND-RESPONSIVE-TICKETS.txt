SPEC: Responsive Design para Escalas de Windows
Fecha: 21/05/2026
Versión: 1.0
Estado: 📋 EN ANÁLISIS
================================================================================

CONTEXTO:
La aplicación fue diseñada en escala 100% (1920x1080). Al cambiar la escala de
Windows a 125% o 150%, se producen desbordes y desalineaciones visuales.

OBJETIVO:
Implementar márgenes adaptativos por escala de Windows que preserven el diseño
original en 100% y mantengan márgenes visibles en 125% y 150%.

ESTRATEGIA:
- Mantener variable --layout-padding-x: 150px como base (escala 100%)
- Usar @media (min-resolution: 1.25dppx) para escala 125%
- Usar @media (min-resolution: 1.5dppx) para escala 150%
- Mantener variables de fuente y spacing con clamp() (escalan suavemente)

DESCRIPCIÓN:

ARCHIVOS AFECTADOS:
- App/Frontend/src/styles/variables.css

CÓDIGO A AGREGAR (al final del :root o como reglas separadas):

  /* Escala de Windows 125% (DPR 1.25) */
  @media (min-resolution: 1.25dppx) {
    :root {
      --layout-padding-x: 100px;
    }
  }

  /* Escala de Windows 150% (DPR 1.5) */
  @media (min-resolution: 1.5dppx) {
    :root {
      --layout-padding-x: 70px;
    }
  }

NOTA: Mantener override de mobile DESPUÉS de estas reglas:
  @media (max-width: 768px) {
    :root {
      --layout-padding-x: var(--spacing-2);  /* 16px en móvil */
    }
  }

TICKET #003 ⏳ PENDIENTE
================================================================================
TÍTULO: Corregir grid responsive en NuevoCalculoPage

PRIORIDAD: 🔴 ALTA
TIEMPO ESTIMADO: 45 minutos
DEPENDENCIAS: Ticket #002

DESCRIPCIÓN:
El grid de 4 columnas (.cardsGrid) genera overflow en escalas 125%+ porque
no permite que las columnas se compriman. Cambiar a minmax(0, 1fr).

ARCHIVOS AFECTADOS:
- App/Frontend/src/pages/NuevoCalculoPage.module.css

CAMBIOS:

ANTES:
  .cardsGrid {
    display: grid;
    grid-template-columns: repeat(4, 1fr);
    gap: 24px;
    max-width: 1400px;
    margin: 0 auto;
  }

DESPUÉS:
  .cardsGrid {
    display: grid;
    grid-template-columns: repeat(4, minmax(0, 1fr));
    gap: 24px;
    max-width: 1400px;
    margin: 0 auto;
  }

  /* Reducir gap en escalas altas */
  @media (min-resolution: 1.25dppx) {
    .cardsGrid {
      gap: 20px;
    }
  }

  @media (min-resolution: 1.5dppx) {
    .cardsGrid {
      gap: 16px;
    }
  }

PRUEBAS:
- Verificar 4 cards completas en escala 100%
- Verificar 4 cards completas en escala 125%
- Si en escala 150% no caben 4 cards: cambiar a 3 columnas (decisión de diseño)

CRITERIO DE ACEPTACIÓN:
✅ Escala 100%: 4 cards alineadas con márgenes del header
✅ Escala 125%: 4 cards visibles sin overflow
✅ Escala 150%: 4 cards visibles (o reorganizadas si es necesario)
✅ Cards no se desbordan del contenedor padre

## Responsive Design

### Sistema de márgenes adaptativos

La aplicación usa márgenes laterales que se adaptan a la escala de Windows:

- **Escala 100%:** 150px (diseño original)
- **Escala 125%:** 100px (vía @media min-resolution: 1.25dppx)
- **Escala 150%:** 70px (vía @media min-resolution: 1.5dppx)
- **Mobile:** 16px (vía @media max-width: 768px)

### Cómo usar en nuevos componentes

✅ HACER:
  .mi-componente {
    padding: 0 var(--layout-padding-x);
    font-size: var(--font-size-xl);
    gap: var(--spacing-3);
  }

❌ NO HACER:
  .mi-componente {
    padding: 0 150px;       /* Píxeles fijos */
    font-size: 24px;         /* No escala */
    gap: 24px;               /* No escala */
  }

### Cómo probar antes de hacer PR

1. Configurar Windows en escala 100% → verificar diseño
2. Cambiar a escala 125% → verificar sin overflow
3. Cambiar a escala 150% → verificar funcionalidad
4. Probar en mobile (DevTools, viewport 375px)

CRITERIO DE ACEPTACIÓN:
✅ Sección documentada con ejemplos
✅ Convenciones claras para futuros desarrollos
✅ Equipo informado sobre el cambio
