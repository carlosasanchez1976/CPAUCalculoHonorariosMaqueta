TICKET-002: Capa intermedia de ajuste de vigencia por rol (Testing)
--------------------------------------------------------------------------------
OBJETIVO:
Permitir que usuarios con rol específico (ej: admin) puedan acceder y probar
tareas profesionales marcadas como "no vigentes" (EN CONSTRUCCIÓN) en la base 
de datos, sin modificar los datos de la API.

ALCANCE:
- Crear constante TAREAS_A_VALID_POR_ROL para configurar excepciones por rol
- Implementar función ajustarVigenciaPorRol() como capa de presentación
- Integrar ajuste en NuevoCalculoPage antes de renderizar cards
- Documentar claramente el propósito temporal de testing

ARCHIVOS CREADOS:
- src/utils/tareasHelper.js (nueva utility)

ARCHIVOS MODIFICADOS:
- src/utils/constants.js (añadida TAREAS_A_VALID_POR_ROL)
- src/pages/NuevoCalculoPage.jsx (integración del ajuste)

LÓGICA IMPLEMENTADA:
1. Se muestran TODAS las tareas (no se filtran)
2. Tareas con vigente=1 → Badge normal, habilitadas para todos
3. Tareas con vigente=0:
   - Si el rol está en TAREAS_A_VALID_POR_ROL → Se fuerza vigente=1
   - Resultado: Sin badge "EN CONSTRUCCIÓN", habilitada para ese rol
   - Otros roles siguen viéndola "EN CONSTRUCCIÓN" y deshabilitada
4. Rol "admin" ve CONFAC y ARBI habilitadas (sin badge)
5. Otros roles las ven con badge "EN CONSTRUCCIÓN" (deshabilitadas)
6. Reordenamiento post-ajuste: vigente DESC + descripción ASC
   - Todas las vigentes (incluyendo ajustadas) aparecen primero
   - Dentro de cada grupo (vigentes/no vigentes) se ordenan alfabéticamente

CARACTERÍSTICAS:
- No modifica datos de API ni base de datos
- Ajusta solo el campo "vigente" en presentación
- Reordena las cards para mantener vigentes juntas
- Capa temporal para testing
- Fácilmente removible cuando termine período de pruebas
- Documentación extensiva en código

CORRECCIONES APLICADAS:
- Versión inicial filtraba las tareas (ocultaba las no vigentes)
- Versión corregida muestra todas, pero ajusta el estado de vigencia
- Ahora las cards "EN CONSTRUCCIÓN" se muestran pero habilitadas para admin
- Agregado ordenamiento post-ajuste para agrupar vigentes (CORRECCIÓN 2026-06-04)

ESTADO: ✅ COMPLETADO
