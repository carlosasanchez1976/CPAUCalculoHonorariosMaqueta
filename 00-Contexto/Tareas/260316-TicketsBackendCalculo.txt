================================================================================
TICKETS - BACKEND API PARA CÁLCULO DE HONORARIOS (SERVERLESS)
================================================================================
Proyecto: CH2026 - Sistema de Gestión de Cálculo de Honorarios CPAU
Fecha: 16/03/2026
Versión: 1.0 - Implementación Serverless (Maqueta)
================================================================================

OBJETIVO GENERAL:
Proteger la lógica de cálculo de honorarios moviendo el código desde el frontend
hacia una API serverless, ocultando coeficientes, fórmulas y reglas de negocio
del navegador del usuario. Esta implementación servirá como base para la futura
migración a un backend completo con base de datos y stored procedures.

JUSTIFICACIÓN:
Actualmente todo el código de cálculo (coeficientes, fórmulas, rangos, etc.) 
está visible en el navegador del cliente, lo que expone propiedad intelectual 
y permite a competidores copiar la lógica. Se requiere ocultar esta información
manteniendo la funcionalidad actual.

ESTRATEGIA DE IMPLEMENTACIÓN:
- Fase 1 (HOY): API Serverless en Vercel (maqueta funcional)
- Fase 2 (FUTURO): Backend real con DB y Stored Procedures
- Principio clave: "API Contract First" - el contrato de API permanece estable

IMPLEMENTACIÓN REALIZADA:
Se crearon DOS estructuras de backend para diferentes propósitos:

   • Solución: Código inline en handler (calcular.js tiene todo el código)
   • Evitar dependencias externas en serverless functions
   • Lección: Mantener handlers autocontenidos en Vercel

3. ❌→✅ Error de CORS al integrar frontend con backend
   • Problema: Variable VITE_API_URL sin el sufijo /api
   • Solución: Configurar VITE_API_URL=https://ch2026-backend-maqueta.vercel.app/api
   • Lección: Verificar configuración de variables de entorno antes de deployment

   • Problema: Confusión entre estructura de rutas
   • Solución: Alinear rutas de Vercel con código del servicio
   • Lección: Documentar claramente la estructura de rutas desde el inicio
